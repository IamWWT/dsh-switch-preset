# 05-testing — 测试计划与报告

## 用途

存放测试策略、测试用例与**带证据的测试报告**。证据 = 你实际运行的命令输出，禁止虚构。

## 文件约定

| 文件 | 内容 |
|------|------|
| `test-plan.md` | 测试范围、策略（单元/集成/E2E）、环境、工具 |
| `report-<日期>.md` | 当次测试报告：范围、命令、结果（通过/失败/跳过）、缺陷清单 |
| `scripts/` | 可重复执行的测试脚本（验证命令固化） |

## 报告模板

```markdown
# 测试报告 <YYYY-MM-DD>

## 范围
（本次覆盖的功能/模块）

## 环境
（语言版本/依赖版本/数据库版本/运行环境）

## 执行
```bash
（真实命令）
```

## 结果
| 用例/套件 | 通过 | 失败 | 跳过 | 备注 |
|----------|:---:|:---:|:---:|------|
| {{suite}} | 12 | 0 | 1 | |

## 缺陷
| ID | 严重级 | 描述 | 状态 |
----|:---:|------|------|
| BUG-01 | P1 | ... | 已修复/打开 |

## 结论
（是否满足 DoD；未覆盖项明确列出）
```

## 测试宪法（摘要）

1. 单元测试：快、确定、可重复、无外部依赖。
2. 集成测试：真实依赖（数据库/Redis 用临时实例或 Testcontainers）。
3. E2E：关键路径必须有（如"创建→查询→删除"）。
4. 测试证据必须能复现：脚本化 + 输出留档。
5. 覆盖率是手段不是目标：优先覆盖核心逻辑分支与失败路径。
