# SDD 规格目录（DSH 插件强制）

> 依据 `dsh-plugins/PLUGIN-DEV-STANDARD.md` 第 3 章：**规格未获用户确认前，禁止进入实现阶段**。

## 约定

每个特性一个目录：`docs/specs/<id>/`（如 `001-board-reveal/`），内含三件套：

| 文件 | 内容 | 检查点 |
|---|---|---|
| `spec.md` | 背景/目标与非目标/**验收标准**/开放问题/确认记录 | **呈现给用户，确认后**才继续 |
| `plan.md` | 技术规划：模块划分/数据流/契约/风险与回退 | — |
| `tasks.md` | 任务拆解：每项含 DoD 与验证命令，逐批可验证 | 完成后勾销 |

`_template/` 下是三件套骨架，复制后改名使用。

## 流程

1. **Specify**：写 `spec.md`（验收标准必须可测）→ 呈现用户。
2. **用户确认**（硬门槛）→ 澄清歧义，结论回写 spec「开放问题」节并标 ✅。
3. **Plan** → **Tasks** → **Implement**（每任务小步提交）。
4. **Converge**：逐条对照 spec 验收标准验证（构建/类型/测试 + UI 验证）；未过不得宣称完成；用户最终确认后才进入安装/分发。
