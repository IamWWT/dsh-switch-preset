# glossary — 术语表

> 新术语随使用增加；定义只此一处，其他文档引用本文（单一真源）。

## 核心术语

| 术语 | 定义 |
------|------|
| AI 项目框架 | 本仓库：让 AI Agent 按既定流程产出生产级项目的规则与模板集合 |
| Agent | 按 AGENTS.md 执行开发任务的 AI 编码代理（Codex / Claude Code 等） |
| 一句话需求 | 用户给 Agent 的最小指令（目标 + 技术偏好 + 约束） |
| 7 阶段协议 | P0 需求 → P1 设计 → P2 计划 → P3 脚手架 → P4 实现 → P5 加固 → P6 交付 |
| Gate（关口） | 阶段间的通过条件与评审点，不可跳过 |
| DoD | Definition of Done，任务"完成"的可验证标准 |
| PRD | 产品需求文档（功能 + 验收标准） |
| ADR | 架构决策记录（背景/决策/影响/备选） |
| FILE_INDEX | 全仓库文档索引（Agent 维护，doc-check 校验） |
| Frontmatter | 文档头部 YAML 元数据（title/type/status/version/...） |
| 单一真源 | 每个事实只存在一处，其他引用不复制 |
| 契约先行 | 接口/数据结构先于实现定义，模块只依赖契约 |
| SPI | 服务提供者接口：定义接口，实现方接入，调用方只依赖定义 |
| CAS | Compare-And-Swap，状态更新带期望值守卫，防并发覆盖 |
| fail-closed | 默认拒绝/关闭；配置缺失则拒绝启动 |
| fail-soft | 可选能力失败时降级但打日志、有兜底 |
| 诚实纪律 | 只宣称已验证事实、写后即验、失败如实记录、证据来自真实执行 |
| 质量门禁 | scripts/quality-gate.sh：语法 + 文档一致性 + 构建测试 |
| 进度日志 | docs/04-progress/，每批实现的真实记录（含失败） |
| 经验库 | docs/06-experience/，教训/踩坑/复盘，跨项目继承 |
| MEMORY | 项目当前状态/待办/硬约束，会话间继承载体 |
| 脚手架 | scaffold/，新项目模板（init-project.sh 实例化） |
| 最小可行栈 | 只选解决问题所需技术；每加组件 = 复杂度，必须有理由 |

## 流程术语

| 术语 | 定义 |
------|------|
| 需求摄入 | P0：把用户一句话转为 request.md + 假设表 + PRD |
| 四维检验 | 模块/Agent 拆分前从上下文纯净度/时间尺度/风险边界/生命周期检验 |
| 能力组织判定 | 新能力先判定形态：Agent / 工具接口 / 普通函数 |
| 依赖矩阵 | 文档变更联动表（必更新项 / 审查项） |
| 需求变更联动 | 需求变更 → 记录 → 评估波及 → 顺流更新 → 重新验证 |
| 文档依赖链 | request → PRD → 架构 → 计划 → 进度 → 测试 → 经验 → 运维 |
| 回归测试 | 修复/变更后证明原有行为未破坏的测试 |
| 契约测试 | 锁定接口请求/响应/错误行为的测试 |
