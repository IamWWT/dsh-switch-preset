# 性能规范

> 原则：**没有基准就没有性能**。先测量，再优化；优化必须有数据支撑。

## 1. 设计期

| 规则 | 说明 |
|------|------|
| 明确负载目标 | 读/写 QPS、P99 延迟、并发数——写进 PRD 非功能需求 |
| 容量预留 | 缓存/连接池/线程池上限可配置，禁止无界 |
| 数据访问模式 | 按访问模式设计索引/缓存/分区，避免"先上线再救火" |
| 批量优于循环 | N+1 查询必须避免（JOIN/批量/预取） |

## 2. 实现期

| 规则 | 说明 |
|------|------|
| 分页用 keyset | 大数据量禁用深 OFFSET（性能随页号恶化）；用游标/`WHERE id > ? LIMIT n` |
| 索引匹配查询 | 慢查询用 EXPLAIN 验证走索引；避免全表扫描 |
| 连接池 | DB/HTTP/Redis 连接池显式配置（上限 + 超时） |
| 缓存有失效策略 | TTL/版本号/显式失效；防止脏数据；缓存不可用有降级 |
| 热路径无阻塞 | 异步/批量处理耗时操作；锁粒度最小化 |
| 序列化最小化 | 大对象裁剪字段；避免无效拷贝 |

## 3. 验证期

| 规则 | 说明 |
|------|------|
| 关键路径基准 | 压测/基准脚本落 `docs/05-testing/`；记录环境与参数 |
| 慢查询审查 | 日志或工具找慢查询，逐一分析 |
| 内存与泄漏 | 长任务/循环/缓存注意内存增长；压测观察 GC 与内存曲线 |
| 对比报告 | 优化前后数据对比，证明优化有效 |

## 4. 常见反模式（禁止）

- 深 OFFSET 分页（>10000 行）
- N+1 查询
- 无界队列/线程池
- 循环里开连接/事务
- 同步等待远程调用链过长（无超时/并行）
- 缓存永不失效且无降级
