# 测试规范（测试宪法）

## 1. 金字塔

```
        / E2E（关键路径，少量）
      / 集成（真实依赖）
    / 单元（多、快、确定）
```

| 层 | 覆盖 | 要求 |
|----|------|------|
| 单元 | 纯逻辑/单模块 | 无外部依赖；毫秒级；确定可重复 |
| 集成 | 模块 × 真实依赖 | 临时实例/Testcontainers/本地依赖；数据隔离 |
| E2E | 关键用户路径 | 冒烟级；环境可重建 |

## 2. 铁律

1. **测试不是装饰**：每个功能必须有能证明它工作的测试。
2. **先写失败测试（关键路径）**：复杂逻辑先写测试定义行为，再实现。
3. **失败路径必须有测试**：错误输入、超时、异常、重试耗尽。
4. **测试可重复**：无随机/时间依赖；必要时注入时钟。
5. **证据落盘**：测试报告 + 真实输出存 `docs/05-testing/`；验证命令固化到脚本。
6. **不 mock 一切**：mock 只用于隔离外部边界；自己的逻辑用真实对象。

## 3. 覆盖目标（非教条）

- 核心业务规则：分支全覆盖；
- 边界条件：空值/极值/非法值；
- 错误处理路径；
- 不追求 100% 行覆盖，但核心模块不得低于合理水平（如 70-80%，按项目定）。

## 4. 报告

报告模板见 `docs/05-testing/README.md`。每个报告必须含：范围、环境（版本）、命令、结果表、缺陷、结论。
