# 接口管理规范（Interface / Contract Engineering）

> 版本: 1.0.0 | 状态: active | 适用范围: 全部对外与对内接口
> 目标：接口是**契约**，不是实现细节。接口的生命周期、版本、文档、兼容性必须有纪律，否则多模块/多 Agent/多团队协作必然互相踩脚。

---

## 1. 契约先行（铁律 #3 的操作化）

| 顺序 | 动作 | 产出 |
------|------|------|
| 1 | 定义接口语义：名称、输入、输出、错误、幂等性 | 接口清单 |
| 2 | 定义数据结构与校验规则 | schema/DTO 定义 |
| 3 | 定义错误模型（错误码、重试语义、HTTP 语义） | 错误码表 |
| 4 | 定义兼容性承诺（版本策略） | 接口版本策略 |
| 5 | 实现契约 | 代码 |
| 6 | 验证契约（契约测试） | 契约测试 |

禁止"先写实现再回头抽象接口"（大项目必经之坑）。

---

## 2. 接口分类与文档要求

| 接口类型 | 文档载体 | 最低要求 |
---------|---------|---------|
| 外部 API（REST/gRPC） | OpenAPI / proto + `docs/07-ops/` 或接口文档 | 每个端点：请求/响应/错误/鉴权/限流 |
| 内部模块契约（SPI） | 接口定义代码 + architecture.md | 每个 SPI：职责、入参出参、实现者约束 |
| 消息/事件契约 | topic/事件 schema | 事件名、字段、幂等键、投递语义 |
| 数据库/存储契约 | 迁移脚本 + 数据字典 | 表结构变更必须走迁移，禁止手改 |
| CLI/脚本 | 帮助文本 + README | 参数、退出码、示例 |

### 2.1 接口文档必须回答的问题

1. 谁调用（调用方/团队）？
2. 什么时候调用（触发条件/频率）？
3. 什么算成功 / 什么算失败（错误语义）？
4. 失败怎么重试（幂等性/退避）？
5. 权限与配额（谁有权、限流多少）？
6. 版本策略（何时升级、何时废弃）？

## 3. 接口版本与兼容性

### 3.1 语义化版本（semver 精神）

| 变更类型 | 版本动作 | 例子 |
---------|---------|------|
| 兼容新增 | minor 或 patch | 增加可选字段/新端点 |
| 破坏性变更 | major | 删除字段/改变语义/改错误码 |
| Bug 修复 | patch | 行为修正（需说明语义变化） |

### 3.2 兼容性铁律

1. **破坏性变更前必须找消费方**：搜索调用点，评估影响，同步迁移计划。
2. **禁止悄悄改语义**：同签名不同行为 = 破坏性变更。
3. **新增字段必须可选或有默认值**，否则视为破坏性变更。
4. **字段重命名走新旧并存**（deprecate → remove 两阶段）。
5. 废弃接口必须：标记 deprecated → 通知消费方 → 至少一个版本周期后移除。

### 3.3 契约测试

- 契约测试锁定接口行为（请求/响应/错误），防止实现破坏契约。
- 消费方模拟与提供方实现各跑一遍契约测试（consumer-driven contract 精神）。
- 接口变更时契约测试必须先改红（证明变更确实影响契约）。

## 4. SPI / 契约面（多团队、多 Agent 协作）

平台与业务（或模块 A 与模块 B）之间：

1. 只依赖**接口契约**，禁止依赖实现类（铁律 #3）。
2. 契约面由一方（平台/上游）发布并治理，变更走评审 + 版本策略。
3. 实现方通过 SPI/依赖注入接入，运行时自动发现。
4. 依赖红线文档化（允许/禁止依赖表），违反即 CI 失败（可用架构测试）。

```text
┌──────────────┐   契约(SPI/接口)   ┌──────────────┐
│  调用方/业务  │ ─────────────────► │  提供方/平台  │
└──────────────┘                     └──────────────┘
  只依赖接口定义                       实现可替换（多实现并存）
```

## 5. 接口评审清单（Gate Review 用）

- [ ] 接口语义完整（成功/失败/重试/鉴权）
- [ ] 数据结构有校验规则
- [ ] 版本策略明确（本次变更兼容性类别）
- [ ] 破坏性变更已找齐消费方并有迁移计划
- [ ] 接口文档已更新（OpenAPI/proto/契约测试）
- [ ] 错误模型统一（错误码/HTTP 语义不随实现漂移）
- [ ] 单一真源：schema 定义只有一份，消费方引用不复制
